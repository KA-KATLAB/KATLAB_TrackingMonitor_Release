# KATLAB TrackingMonitor v0.4.4.0 - Workspace Command Masthead

## A clearer workspace brief

The shared masthead gives repository scope, the exact workspace summary and
qualified secondary facts distinct lines. Full repository and branch values
wrap naturally. The existing Repository status action follows the brief on
narrow screens and sits beside it from 768px. The loaded UI build remains beside
the product name, with its unchanged System health action.

The header keeps one column below 1280px, then uses a content-sized brand track
beside flexible, wrapping actions. Scope 1.25rem, summary 1rem and secondary
0.8125rem text provide hierarchy without adding a font, illustration or animation.
These equal 20px, 16px and 13px at the default 16px root. This is a
shared six-view presentation change, not a new metric or readiness promise.

## Truthful attribution guidance

An event without available task choices no longer claims that no tasks exist.
An empty, malformed or non-array candidate declaration can coexist with a
populated repository task catalog. The guidance explains missing choices, not
an empty catalog, and does not promise that adding a plan makes the event pickable.
Candidate parsing, selection, resolver outcomes and assignment remain unchanged.

## Preserved boundaries

Every workspace summary calculation, conditional qualifier and displayed value
remains unchanged. Pending, failed, selected-missing, no-repository, offline,
unknown Git and retained-refresh states stay distinct. Keep Branch versus
Last-known branch, capture age/no captures, unknown/unavailable counts and
discipline warnings. The single Repository status callback stays native/shared.

One scoped sixth inline style intentionally overrides only the reviewed header
and context presentation. All five previous inline bodies and full eager,
Overview and Mission CSS remain byte-identical. View composition, data requests,
scroll/focus ownership, dialogs, persistence and dependencies are unchanged.
Historical preservation projections retain old assertions without rebasing
their hashes. Current behavioral checks continue to execute current source.

## Verification and activation

Require five whole clean CDD passes and five whole clean CFT passes, focused
and full regressions, offline Chronicle verification, installed builds, 17
retained compiled contracts and the new masthead gate. Compare complete
isolated/production results. Actual results and commit identity belong in the
detailed plan after execution, not in advance of verification.

Follow the [safe upgrade procedure](Docs/Installation_Guideline.md#safe-stop-and-restart).
Reprove the deployed v0.4.3.2 instance and native ownership before standard stop.
Both tracker and demo ports must be clear before production build. Use the
standard Hidden restart, then verify the current version, six inline styles,
reachable assets, APIs, watcher readiness, Chronicle pages, current notes and
complete reader CSS. Reload existing tabs to load the new UI build.

## Declared limits

Native H.1/operator beauty, paint, first-viewport fit, reflow, keyboard/focus,
coarse input, zoom and assistive-technology acceptance remain OPEN. Controlled,
SSR, compiled and keep-alive HTTP evidence does not prove native interaction
or visual quality. The known large Connection:close response-body fault remains
unresolved. Existing high advisory 15, chunk, Tailwind and SSR diagnostics are
qualified historical limits, not fixes delivered by this release.
Accepted limitations do not waive any new regression.
