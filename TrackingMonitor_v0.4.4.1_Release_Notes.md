# KATLAB TrackingMonitor v0.4.4.1 - City District Brief

## A readable view of the visible districts

City adds a native brief above its existing scene. Full repository identities
open the existing scoped Overview. Each district pairs qualified Git status
with its actual number of tasks marked in progress. Offline and unavailable
observations stay distinct from current clean or exact uncommitted counts.

The brief uses the same six-district page and configured order as the scene,
with the existing repository range and an explicit workspace-wide qualifier.
It uses one column below 768px, two from 768px and three from 1280px. Long
identities and values wrap rather than being shortened. No productivity,
freshness, workload or verification-readiness claim is added.

## Preserved City ownership

The new component renders only after the existing accepted-snapshot gate.
Waiting, loading, failure, retained data and Retry keep their current owners.
The brief does not issue requests, sort data, add state or change page memory.
Zero districts shows an explicit empty message without creating fake data.

All scene calculations, shared full-workspace scales, buildings, weather,
transient retirement and reduced motion remain unchanged. The brief sits
outside the SVG export container, so snapshot range and content are preserved.
The current pager and complete exact-data disclosure remain independently usable.

One pure component and City-lazy stylesheet are added. All six entry style
bodies and complete eager, Overview and Mission CSS stay byte-identical.
Shared controls retain focus and enabled/disabled/coarse behavior. No font,
dependency, image/icon asset, clock, timer, persistence, API or transport change is included.

## Verification and activation

Require five whole clean CDD passes and five whole clean CFT passes, focused
and full regressions, offline Chronicle checks, installed builds, eighteen
retained compiled contracts and the new City brief gate. Compare complete
isolated and production results. Actual outcomes and full commit identity
belong in the detailed plan after execution, not in advance of verification.

Follow the [safe upgrade procedure](Docs/Installation_Guideline.md#safe-stop-and-restart).
Reprove the deployed v0.4.4.0 instance and native ownership before standard stop.
Both tracker and demo ports must be clear before production build. Use the
standard Hidden restart, then verify the current version, all six entry styles,
reachable City assets, APIs, watcher readiness, Chronicle pages, current notes
and complete reader CSS. Reload existing tabs to load the new UI build.

## Declared limits

Native H.1/operator beauty, paint, first-viewport fit, reflow, keyboard/focus,
coarse input, zoom and assistive-technology acceptance remain OPEN. The added
brief can increase page height; it does not certify a smaller first viewport.
Controlled, SSR, compiled and keep-alive HTTP evidence cannot certify native
interaction or subjective visual quality. The known large Connection:close
response-body fault remains unresolved. Existing high advisory 15, chunk,
Tailwind and SSR diagnostics are qualified historical limits, not release fixes.
Accepted limitations do not waive any new regression.

Previous [v0.4.4.0 notes](Docs/Release_Notes/Archive/TrackingMonitor_v0.4.4.0_Release_Notes.md)
remain archived with only their two moved relative documentation URLs corrected.
