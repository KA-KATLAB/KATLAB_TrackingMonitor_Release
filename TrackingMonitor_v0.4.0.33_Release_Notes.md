# KATLAB TrackingMonitor v0.4.0.33 - Repository-Aware Session Groups

## Fixed

Session Timeline starts a new display group when the repository changes, even
when adjacent captured events share the same task label. A page beginning in
another repository no longer claims to continue the previous repository's run.

Same-repository continuation, changed and unresolved labels, raw row identity,
order, effort/gaps, bounded paging and session disclosure stay intact.
One initializer changes; no requests, deadlines, retries, cleanup or styling.

## Scope and verification

Controlled accepted-state tests execute the complete actual component and
shared format/theme/paging code. They reproduce adjacent and page-boundary
failures against the actual original source, then protect the single predicate
through a strictly owned initializer inverse and immutable original hashes.

A shared test-only inverse precedes exactly three ancestral preservation
pipelines. Their original hashes, pre-render assertions, direct comparator and
disclosure checks and behavioral tests remain unchanged. Every other test stays.

These are repository-qualified display runs, not canonical task identities or
new relational joins. Compatibility task labels and raw normalized plan/task
fields remain separate. No assignment inference, normalization, backend data,
API, schema, configuration, dependency or migration change.

Controlled SSR and live HTTP/assets do not establish native focus, keyboard,
geometry, assistive acceptance or accessibility compliance. Native v0.4 H.1
remains pending under independent-delivery authority. Earlier launcher fixture
limits and the unused synthetic runtime row remain separate. No cleanup or
browser bypass is authorized.

The build-only `braces` issue remains open in the
[primary advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
No dependency migration or chunk-notice suppression.

Use the [safe upgrade procedure](Docs/Installation_Guideline.md#safe-stop-and-restart).
Rebuild after version changes; restarting Python alone leaves old UI assets.
Evidence and publication details are recorded separately in
`temp/Plan/PLAN_v0.4.0.33_Repository_Aware_Session_Groups.txt`.

Previous [v0.4.0.32 notes](Docs/Release_Notes/Archive/TrackingMonitor_v0.4.0.32_Release_Notes.md)
retain their historical content with only two move-affected links rebased.
