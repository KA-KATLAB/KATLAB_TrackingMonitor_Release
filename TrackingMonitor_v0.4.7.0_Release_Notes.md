# KATLAB TrackingMonitor v0.4.7.0 - Changes Task Review Brief

## Understand the work before the reference

Grouped Changes now presents the actual task title as the primary h4 heading,
with the complete technical task reference as secondary context. Repository and
existing effort remain visible, followed by the unchanged Why and captured
event evidence. No reference is hidden behind another control or disclosure.

Titles come only from the task already resolved by repository and task identity.
Missing, deleted, empty, whitespace-only or defensively invalid titles fall back
to the complete existing reference. Never fabricate a title, task status,
confidence, readiness or attribution outcome. Test trimmed text only for
validity; display valid title text unchanged. Retain secondary reference context
even when its value equals the title; fallback headings do not duplicate it.

## Preserve the review workflow

Keep both 50-item event pagers, group ordering, filters, anchors, reveal behavior,
plan-file disclosure and all Diff, Retry, Hide, session and File Story actions.
Long titles and references remain readable and wrap without truncation, HTML
insertion or a new scroller. Queue assignment, folder grouping and other views
retain their existing owners.

Add no request, API/schema change, state, effect, storage, URL state, timer,
dependency or shared-control owner. Preserve every existing stylesheet and
inline style, and verify actual emitted CSS rather than inferring unchanged
output from the absence of a stylesheet edit.

Historical source inputs may be restored only through exact reviewed assertion
adapters with whole-native/LF inverses. Current source, runtime and compiled
artifact readers stay raw; reconstructed old App code is never executed.

## Verification and activation

Require whole CDD5/CFT5, focused current-source and negative cases, formal
focused/full Node/Python verification, builds, all retained compiled checks and
the current Brief gate, with complete isolated/production object parity.
Actual outcomes and the full commit ID belong in the detailed plan after the
checks run. These notes do not claim future checks passed or native acceptance.

Follow the [safe upgrade procedure](Docs/Installation_Guideline.md#safe-stop-and-restart).
Reprove the deployed v0.4.6.0 instance and native owned process forest, stop
normally and confirm tracker/demo ports clear before the production build.
Use the standard Hidden restart and verify canonical version, complete reachable
assets, APIs, watchers, Chronicle pages, current notes and exact reader CSS.
Reload existing browser tabs to load the new UI build.

## Declared limits

Native operator aesthetics, paint, first-viewport fit, responsive geometry,
keyboard/focus, coarse input, zoom and assistive technology remain OPEN.
Source, controlled rendering, compiled assets and keep-alive diagnostics do
not establish native acceptance. The known large HTTP Connection:close body
fault, existing high dependency alerts and inherited chunk, Tailwind and SSR
diagnostics remain OPEN. Accepted limits never waive a new failure or authorize
an ad-hoc dependency, browser, OS or transport workaround.

Previous [v0.4.6.0 notes](Docs/Release_Notes/Archive/TrackingMonitor_v0.4.6.0_Release_Notes.md)
remain archived with only their moved relative documentation URLs corrected.
