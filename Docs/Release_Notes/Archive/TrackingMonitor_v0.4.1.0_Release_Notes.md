# KATLAB TrackingMonitor v0.4.1.0 - Mission Control Workbench

## Visible workbench

A larger complete KATLAB identity and decorative monogram lead the header.
The bordered build badge remains a real button opening the same System health
dialog. Quieter utilities, a separate context line and a clear current-view
border retain all six routes, labelled actions and readiness/focus ownership.

Changes adds three definition-list summaries: Needs attribution, Captured
edits and Task groups. They describe the complete current loaded capture model,
not Git dirty files, whole-workspace completeness or a clean guarantee. The
queue remains unfiltered; task groups keep task/session filters, including the
explicit saved-filter description in folder mode.

The summary stacks below 768px and uses three columns from 768px. At 1440px with
an unresolved queue, attribution and grouped work share a two-column workbench;
attribution remains first in DOM. Narrow/no-pick layouts stay stacked. Existing
filters, anchors, main scrolling, 50-item presentation, selection, assignment,
partial outcomes, deadlines, retries, sessions and inline diffs remain intact.

## Verification and known limitations

Regression coverage uses actual current component/builder owners, installed
Mermaid semantic owners and public grammar, matching-version gate fixtures and
strict physical/source-oracle inverses. Original hashes, assertions, negatives
and the old Diff prefix are preserved, rather than rebased to hide changes.
Results and delivery evidence are recorded separately in
`temp/Plan/PLAN_v0.4.1.0_Mission_Control_Workbench.txt`.

Recorded large Connection: close responses can stall before the complete
advertised body arrives. One exact diagnostic received 783360 of 808669 bytes
without EOF before a 10-second timeout. Bounded keep-alive HTTP success does
not repair that path. The isolated bare-Proactor comparison also failed; no
speculative transport, stdlib, environment or dependency fix is included.

Native v0.4 H.1 remains pending. Source/SSR/hooks/HTTP/assets do not certify
paint, geometry, keyboard, focus, assistive technology, PWA, security or
accessibility. Responsive widths, 200% zoom, coarse input, safe areas, long
content and loading/empty/error/stale/reduced-motion states remain operator
acceptance checkpoints. The user explicitly accepts publication with these
recorded transport and native limitations; they are not claimed fixed.

The previously recorded high build-only braces advisory and build chunk notice
are not addressed. GitHub alert status was not refreshed in this cycle.
No forced dependency migration or browser workaround.
No API, schema, backend runtime, configuration or stored-data change is added.

Use the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).
Rebuild the frontend from matching source and reload existing tabs; restarting
Python alone leaves the old loaded UI assets. Actual owned stop/start, live
checks, commit ID and existing remote refs are documented in the plan.
