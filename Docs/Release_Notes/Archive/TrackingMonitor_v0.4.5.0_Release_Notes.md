# KATLAB TrackingMonitor v0.4.5.0 - Active Plan Docket

## Current work first, details on demand

Overview's Active plans changes from always-expanded cards into a compact
docket. Each plan keeps full repository/plan identity, exact completion counts
and truthful marked-in-progress context visible before its additional details.

Independent native disclosures let the operator inspect more than one plan.
The browser owns opening and closing, without custom toggle state, exclusive
accordion groups, extra requests or saved preferences. Existing task explanations,
concrete-path File Story actions, declared patterns, file previews, next pending
task and the complete exact-data table remain available.

## Bounded task presentation

The existing plan pager still displays at most 50 plans. Each plan now also uses
the existing shared 50-item pager for its marked-in-progress task cards, fixing
a previously unbounded semantic inner list. Counts and the exact-data table use
the complete model. The decorative task-status segments retain their original
meaning. Closed details are not virtualization or a global mounted-node bound.

Keep repository/plan composite identity, grouping, sorting, caller readiness
gates, retained-snapshot warnings, declared-file semantics and callbacks.
No fresh-work, readiness or successful-verification claim is inferred from style.

## Presentation and verification

A scoped stylesheet is imported after the unchanged Active Plan Gallery CSS,
inside lazy Overview ownership. Other view layouts, the seven entry styles,
eager/Mission/City CSS, unrelated Overview rules, fonts and dependency manifests
remain unchanged. Full identities wrap and summary controls retain native cues
with explicit target size and visible focus.

Require whole CDD5/CFT5, exact preservation adapters, current-runtime regression
and negative cases, focused/full tests, builds and compiled ownership checks.
Record actual outcomes and the full commit ID in the detailed plan after running
them, not in advance.

Follow the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).
Reprove the old v0.4.4.2 instance and native ownership, stop it normally, and
confirm both tracker/demo ports clear before production build. Use the standard
Hidden restart and verify the new canonical version, complete reachable assets,
APIs, watchers, Chronicle pages, notes and reader CSS. Reload existing browser
tabs to load the new UI build.

## Declared limits

Native operator beauty, paint, first-viewport fit, responsive geometry,
keyboard/focus, coarse input, zoom and assistive technology remain OPEN.
Source, controlled rendering, compiled assets and keep-alive diagnostics do
not establish native acceptance. The known large Connection:close body fault
and existing high advisory 15, chunk, Tailwind and SSR diagnostics remain OPEN.
Those accepted limitations never waive a new failure.

Previous [v0.4.4.2 notes](TrackingMonitor_v0.4.4.2_Release_Notes.md)
remain archived with only their moved relative documentation URLs corrected.
