# KATLAB TrackingMonitor v0.4.1.1 - Overview Operations Deck

## Visible operations deck

Overview's existing Now section gains a subdued frame, four primary metric
panels and a quieter captured-activity strip. Attribution decisions lead;
known Git changes, known clean-repository coverage and dated effort follow.
Captured events, auto-attribution and the optional busiest task stay secondary.
No summary, data source, interaction owner or semantic markup is invented.

Both groups stack below 768px. From 768px the primary deck uses two equal
columns and the secondary strip uses three. From 1024px the first metric spans
two rows in a three-column asymmetric deck; dated effort spans columns 2-3 on
the second row. DOM/read order and natural height/wrapping remain unchanged.
The first metric's neutral sky accent applies to all states, not just measured
needs, and does not imply warning, readiness or completeness.

Existing primary/secondary values stay 32px/20px. Panel gaps/padding are
16-24px, the heading divider uses 12px padding, secondary inner metrics use
zero padding, and corners remain 8/12px. There is no font scaling, fixed or
clipped height, new animation, sticky layer or scroll owner.

## Preserved state and interaction owners

This is scoped CSS presentation only. All React/TypeScript production owners,
requests, timers, hooks, callbacks, state and dependencies remain unchanged.
Waiting and unavailable workspace data, accepted no-repo/unknown/offline
coverage, measured zero and retained snapshots remain distinct. Exact dates,
approximate effort, independent stats/workspace states and existing count-up
and reduced-motion behavior are preserved.

PlanBoard is still driven by stats and workspace acceptance, not event totals.
Momentum and trend/exploration panels keep their positive-event gates, UTC
bounds and full models. All six views retain navigation, selection, filters,
main scrolling, paging, dialogs, focus and existing error/recovery owners.

## Verification boundaries and known limitations

The new regression suite checks the complete literal CSS block, insertion
site, scoped declarations, responsive contracts and strict whole-stylesheet
inverse. Raw-current Kpi fixtures use real format/day helpers and an explicit
reduced-motion final state. Complete Overview and existing regression bytes
remain pinned; no original hash or assertion is rebased to conceal changes.
Actual review, CFT, test and delivery evidence is recorded separately in
`temp/Plan/PLAN_v0.4.1.1_Overview_Operations_Deck.txt`.

Native v0.4 H.1 remains pending. CSS/source/SSR/hooks/HTTP/assets do not certify
paint, geometry, keyboard, focus, assistive technology, zoom, coarse input,
safe areas or native loading/empty/error/stale/reduced-motion behavior.

The recorded large Connection: close response failure remains open. Bounded
keep-alive diagnostic success is not a repair. The previous high build-only
braces advisory and build chunk notice are not addressed. Historical GitHub
push alert notices are not a fresh advisory-detail audit or remediation.
No API, schema, backend runtime, configuration, stored-data, dependency,
security, transport or browser workaround is introduced.

The user explicitly accepts limited publication with the recorded native and
transport limitations. They are not claimed fixed; new blocking regressions
must stop publication.

Use the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).
Stop tracker and demo before rebuilding the frontend from matching source;
restart through the standard hidden launcher and reload existing tabs. A
Python restart alone does not update served or already-loaded frontend assets.
Commit ID, live checks and existing remote refs belong in the plan, not guessed
results here.

Previous [v0.4.1.0 notes](TrackingMonitor_v0.4.1.0_Release_Notes.md)
retain every historical byte except their two move-affected Markdown URLs.
