# KATLAB TrackingMonitor v0.4.0.15 - Repository Release Identity

## Fixed

Release-moment replay protection now uses the repository + full commit hash pair.
Two working copies sharing a commit no longer suppress the second repository's
release or baseline update. Its later fourth-part patch rider therefore does not
incorrectly appear as a new release line.

Version-END and three-part-prefix rules, silent first-baseline seeding, history
race protection, same-repository replay suppression, banner stack/replacement and
nonce timers remain. Optional OS alerts, sound and reduced-motion guards retain
their existing ownership and behavior.

## Scope and verification

Actual-handler/seed controlled-boundary regressions reproduce this supported
shared-history topology, not a live incident. The whole-App pre-render oracle allows
only the precise identity edits. Native visual, keyboard, OS notification and
sound acceptance remain pending; effect spies are not delivery evidence.
No API, request, setting, dependency, layout, capture or generated-content changes.

The build-only `braces` advisory remains open; no direct patched version is listed
in the [primary advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
No Tailwind major migration or security remediation is bundled. The existing
large-chunk notice and earlier unconfirmed launcher-fixture transient remain
known limits.

Use the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).

`temp/Plan/PLAN_v0.4.0.15_Repository_Release_Identity.txt`.
