# KATLAB TrackingMonitor v0.4.4.2 - Purpose-Led Navigation

## Know where each view leads

The six existing view choices pair their exact labels with short, static purpose
copy. Changes describes captured file changes; Mission names plans, checks and
evidence; Overview describes activity and project summaries; History states
captured commits; City remains workspace-wide; Chronicle names documentation
and release notes. Purpose copy is wayfinding, not a live status or readiness claim.

Both the desktop Workspace rail and the Navigation drawer use the same source
owner. Labels stay first, with visible purpose beneath and an explicit separating
space in native text. No conflicting accessible label, fixed IDs or hidden
meaningful purpose is added. The navigation remains one tier.

## Preserved behavior and presentation boundaries

Keep the exact six labels, order, keys, native type, current-page marker and
onSelect arguments. The existing three membership-dependent choices retain their
disabled guard. Routing, scope, loading/error/retained state and data requests do
not change. The ordinary button and existing overlay retain focus ownership.

Six scoped CSS rules give labels and purpose copy clear hierarchy and full
wrapping. Label text is 1rem/600; purpose is 0.8125rem/400 with 1.5 line height.
The existing 3rem fine-input minimum height is retained, equivalent to 48px at
the default 16px root. Shared colors, selected/hover states, border markers,
disabled opacity, focus rings and coarse-important declarations keep their owners.

One seventh inline entry style is added. All six previous style bodies and
complete eager, Overview, Mission and City CSS remain byte-identical. No new
font, package, image/icon asset, state, timer, persistence or API work is included.
The desktop local scroller and drawer body scroller stay unchanged. Additional
copy can increase navigation height; no first-viewport fit is certified.

## Verification and activation

Require five whole clean CDD passes and five whole clean CFT passes, exact
preservation-input inverses, raw current-render regressions, focused/full
checks, offline Chronicle, installed builds, nineteen retained compiled
contracts and the new navigation gate. Compare complete isolated/production
result objects. Actual outcomes and the full commit identity belong in the
detailed plan after execution, not in advance of verification.

Follow the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).
Reprove literal deployed v0.4.4.1 and native ownership before standard stop.
Both tracker and demo ports must be clear before production build. Use the
standard Hidden restart, then verify v0.4.4.2, seven ordered entry styles, all
reachable bundles, APIs, watchers, Chronicle pages, current notes and full reader
CSS. Reload existing browser tabs to load the new UI build.

## Declared limits

Native H.1/operator beauty, paint, geometry, first-viewport fit, keyboard/focus,
coarse input, zoom and assistive-technology acceptance remain OPEN. Source,
controlled rendering, compiled and keep-alive HTTP evidence cannot certify
native interaction or subjective quality. The known large Connection:close
response-body fault remains unresolved. Existing high advisory 15, chunk,
Tailwind and SSR diagnostics remain qualified historical limits, not fixes.
Accepted limitations never waive a new regression.

Previous [v0.4.4.1 notes](TrackingMonitor_v0.4.4.1_Release_Notes.md)
remain archived with only their two moved relative documentation URLs corrected.
