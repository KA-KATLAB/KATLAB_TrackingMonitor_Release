# KATLAB TrackingMonitor v0.4.3.2 - File Story Evidence Timeline

## A clearer file history

File Story separates each event's timestamp from its attribution evidence.
Narrow layouts stack in reading order; from 640px a bounded timestamp rail
sits beside the flexible MODE, task, session and differing-branch details.
The full file title, editor link and Close remain in the existing dialog.
Repository and captured-window facts receive separate readable lines.

All displayed values, qualifications and semantic colors remain unchanged.
The chronological day and continuation captions, full-window effort and commit
counts, and 50-row pager retain their existing behavior. Loading, empty, error,
retry, retained data and fetched-window notices remain truthful and visible.

## Preserved boundaries

The collector still requests at most three 500-event pages, deduplicates by
first event identity and sorts by the existing timestamp/id comparator.
No new state, API, persistence, timer, motion or filtering is added. Keep the
same deadline, abort, retry and disposal owners. DialogShell continues to own
modal focus, closing and scrolling; no additional scroller is introduced.

This refinement reuses utilities already emitted for the current UI. Require
all eager, Overview and Mission CSS plus the five entry styles to remain
byte-identical. App, Mission, shared components and dependencies are untouched.
Exact bounded render inverses preserve historical assertions; behavioral
checks continue to execute current File Story source.

## Verification and activation

Require five whole clean CDD passes and five whole clean CFT passes, focused
and full regression checks, offline Chronicle verification, installed builds,
all sixteen retained compiled contracts and a new File Story gate. Compare
complete isolated/production results. Actual outcomes and commit identity
belong in the detailed plan after execution.

Follow the [safe upgrade procedure](../../Installation_Guideline.md#safe-stop-and-restart).
Reprove the deployed v0.4.3.1 instance and ownership before the standard stop.
Tracker and demo ports must both be clear before production build. Use the
standard Hidden restart, then verify current assets, API, watcher readiness,
Chronicle pages, current notes and complete reader CSS. Reload existing tabs.

## Declared limits

Native H.1/operator beauty, paint, reflow, keyboard/focus, coarse input, zoom
and assistive-technology acceptance remain OPEN. Controlled/SSR/compiled and
keep-alive HTTP checks do not prove native interaction or visual quality.
The known large Connection:close response-body fault is unresolved. Existing
high advisory15 and chunk/Tailwind warnings are not fixed by this UI change.
Accepted limitations do not waive new regressions.

Previous [v0.4.3.1 notes](TrackingMonitor_v0.4.3.1_Release_Notes.md)
remain archived with only moved relative documentation URLs corrected.
