# KATLAB TrackingMonitor v0.4.3.0 - Mission Command Desk

## Navigate the current Mission without changing its route

Mission gets a named Command desk for Now, conditional Plans, Forecast,
Verification, Evidence and Flight recorder. The controls precede the same
content in normal flow; from 1536px they occupy a 12rem rail beside it. Below
that width they wrap above the content. All original sections stay mounted in
their original order. The page heading, Refresh, error/loading notices and
Assignment dialog remain outside the new composition.

Plans is offered only when the existing Plan scope section is present. The
desk does not infer readiness, choose a plan, change a filter, select a session,
start replay, refresh data or hide panels. Native type=button controls name the
existing focusable section headings. There are no fragment links, history
writes, new route entries, sticky panels, extra scrollers or automatic jumps.

The surface uses 16px padding, 8px corners and semantic colors. Its title uses
20px/1.4; supporting copy uses 12px/1.5 and controls 14px/1.5 with a 44px minimum
height and natural wrapping. Content keeps 24px section separation. Selected
Now retains its mark and surface, with 20px padding and 24px from 768px. Keep
the existing shared navigation, focus, disabled, coarse-input and motion owners.

## Owned focus, unchanged Mission data

A section jump validates the connected trigger, unique H3 destination, same
desk and existing main scroller, visibility, inert ancestors, overlay lease
and finite geometry. Only a valid explicit click invokes the additive App
callback. It synchronously clears a pending route-focus request through the
existing flushSync owner, then revalidates the same live nodes. Focus uses
preventScroll; final geometry is recomputed and only main.scrollTop is clamped.
Detached/replaced/duplicate/hidden/disabled owners, overlays or invalid geometry
reject the jump. Focus-triggered invalidation is checked before scrolling.

Keep the original route-focus effect, generation, hydration/retry behavior,
entry identity, history and navigation owners unchanged. The source-backed
cleanup argument is tied to installed ReactDOM 18.3.1/createRoot; controlled
effect/DOM hosts and vendor predicates are not native browser execution or a
guarantee for a future React version. A later genuine navigation keeps its
independent focus intent. The cancellation callback itself never jumps.

Mission snapshots, independent errors, loading/unavailable/accepted-empty
states, backend readiness and exact repository/plan keys remain authoritative.
Keep 12-plan paging and existing 50-item reason, requirement, evidence, session,
timeline and assignment windows. Provider + session identity, deterministic
activity order, replay/reduced-motion handling, Exact Data, request retirement,
deadlines, Refresh/Retry and assignment acknowledgements stay unchanged.
