# KATLAB TrackingMonitor v0.1.12.0 — Release Notes

**Theme:** Momentum & Presence — know your trend, feel the tracker outside the tab.

Tenth harvest cycle (KPI-delta dashboard staple, Badging API class): a week-over-week momentum strip answers "am I speeding up?" at a glance, and the tracker becomes an installable PWA whose taskbar icon carries the live uncommitted count. The plan survived an 8-pass CDD review loop (3 findings RV1–RV3 fixed in place, ending 5/5 consecutive clean), with the delta math dry-run-proven on the live database and the `/icons` startup-crash hazard caught — and designed out — before a line was written.

## Highlights

- **Momentum strip:** a slim three-tile band between the KPIs and the charts — captures, effort, and commits, each showing this week's total, a delta chip vs last week, and a 14-day sparkline where the prior week renders dimmed behind the current one. The delta rule is honest: no percentages against zero (a first-activity week says "new ▲", not "∞%"), and a down week renders slate, not red — a light week is not a failure. Both windows come straight from the served activity calendar; zero new backend data.
- **Install it (PWA):** Chrome/Edge now offer "Install app" — the tracker opens in its own standalone window with the KATLAB ring mark on your taskbar. To install: open `http://127.0.0.1:8100`, click the install icon in the address bar (or ⋮ → Cast, save and share → Install). The icons are generated by a stdlib-only Python script (committed PNGs, no new dependencies); the service worker is deliberately **network-only** — this is a live tracker, nothing is ever cached.
- **Taskbar badge:** once installed, the app icon carries the live uncommitted count — exactly the ALL-tab "uncommitted changes" KPI (offline repos excluded, so a stale count never lands on your taskbar) — and clears the moment everything is CLEAN ✓. Honest limit: the Badging API works on the **installed** app while its window runs (Windows/macOS Chrome/Edge); the browser tab alone shows no badge, and there is no push machinery — the bell keeps owning alerts.

## Cross-repo

Nothing to install in monitored repos, no database migration, no API or schema change — the backend diff is the version constant plus four static-serving routes in `main.py` (manifest, service worker, two icons; explicit routes rather than a directory mount, so a stale frontend build can never take the server down at startup). Zero new dependencies (`package.json` untouched); no new localStorage keys.
