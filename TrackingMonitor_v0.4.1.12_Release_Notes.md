# KATLAB TrackingMonitor v0.4.1.12 - Provenance Evidence Desk

## Captured evidence, with a clearer basis

Overview retains its existing full-width Provenance card below Trophy/Records.
The measurement and ranked-file ledger now have separate panels instead of a
cramped percentage/basename list. The real h4 heading, scope description, quiet
Surface, reveal and positive-event/statistics gates keep their owners.

The unchanged metric counts observed committed file changes per commit/file,
starting from each repository's first capture and excluding plan-file slots.
Linked capture lookup uses the repository/commit pair; it is not authorship,
lines of code, unique files or complete historical commit coverage. Clean
sweeps can attach retained/reverted edits to HEAD. Unlinked changes do not
prove human-only work. Correct only the card's obsolete Claude/human wording;
the existing App Legend's stale Claude-only prose is outside this release.

Keep pctOf's exact, defensive and intermediate 1..99 policy, both raw ratios
rounded to one decimal for decorative bars, supplied counts, singular/plural
and earlier-excluded copy. No scope recount or new telemetry is introduced.
Zero slots still hide the entire card. Positive slots without ranked rows
now explicitly describe that snapshot absence.

## Full paths and shared actions

The backend's at-most-eight rows retain commits-descending/repo/file order,
composite keys and exact counts. Show complete row.file rather than basename,
so same-basename paths remain distinguishable. All-repo labels keep their
undefined-scope predicate; existing empty-string scope behavior is unchanged.
React escapes raw path/repository text without mutating the supplied rows.

With the existing callback, a shared native button opens exactly repo/file;
its accessible name and title include the repository as well as the full path.
Without a callback, render a static path and do not promise an opening action.
There are no new requests, handlers beyond that existing action, hooks, state,
storage, clocks, sorting or attribution owners.

## Responsive measurement and ledger panels

Stack below 1024px viewport width. From that boundary, use zero-minimum
0.7fr/1.3fr columns and 16px gaps, with 16px panel padding, shared 1px borders,
8px corners and surface tone. The navigation rail reduces the containing
block's available width; do not equate it with the entire viewport.

Measurements use 32px/40px tabular configured Azeret Mono; labels and full-path
actions use 16px/24px, copy 14px/21px and row metadata 12px/18px. Paths, labels
and values wrap anywhere. Ledger rows use 12px vertical padding and wrapped
metadata; only the final ratio span has an automatic left margin.

File actions declare normal 44px minimum height. Existing coarse
44px-important minima, shared focus/hover/press and reduced-motion owners
retain priority and behavior. These declarations are not native hit-area
proof. No clipping, truncation, fixed height, positioning, reordered content,
new scroll owner, font resource or animation is introduced.

The single stylesheet import belongs to Provenance, loaded only with lazy
Overview beside Gallery/Momentum/Achievement, not eager Records. The new
stylesheet is 81 LF lines/2540 bytes: one comment, ten direct root rules and
one 1024px media containing one direct child rule. All selectors are scoped
to the marked Surface, without global rules, important priority or resources.

must protect the complete approved source. Actual current Vite SSR uses the

Existing operational/Overview/Trophy/Records/Momentum/weekly/year/UI suites
must also execute, not merely match source fingerprints.

Validate all eleven compiled Desk rules before subtracting only validated
nodes from a clone and restoring every old1.11 lazy stylesheet byte.

and every old assertion; never rewrite built files or relax a historical SHA.
